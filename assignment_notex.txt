2. Data preparation
- Randomly sampled 150,000 rows from ratings.csv with fixed random seed
- Used the same sampled ratings file for both recommender systems
- Aggregated tags by movieId into one tags_text field
- Cleaned title, genres, and tags
- Replaced genre separator "|" with spaces for profile text
- Built one movie text profile per movie:
  title + genres + tags
- Main output files:
  - outputs/ratings_sample_150k.csv
  - outputs/movie_tags_aggregated.csv
  - outputs/movie_profiles.csv
  - outputs/ratings_with_movie_profiles.csv

3. RS1 — Conventional recommender
- Type: personalised content-based recommender
- Representation: TF-IDF vectors from movie profile text
- User profile: average TF-IDF vector of movies rated >= 4
- Ranking method: cosine similarity
- Output: top-N unseen movies
- User eligibility for recommendations: at least 5 positive ratings
- Explanations: similar to liked films + genre/theme wording

Why RS1 fits:
- Movie metadata is naturally text-based
- Genres and tags map well to TF-IDF
- Fast baseline
- Transparent and easier to explain than deep models

4. RS2 — Advanced recommender
- Type: advanced extension of RS1
- Same overall pipeline as RS1
- Only main change: replace TF-IDF item vectors with SBERT embeddings
- Model used: sentence-transformers/all-MiniLM-L6-v2
- User profile: average embedding of movies rated >= 4
- Ranking method: cosine similarity
- Output: top-N unseen movies
- User eligibility for recommendations: at least 5 positive ratings
- Explanations: semantically close to liked films + theme wording

Why RS2 fits:
- Captures semantic similarity beyond exact keyword overlap
- Still works well with short movie profile text
- Minimal pipeline change keeps comparison fair
- More advanced than TF-IDF but still practical to implement

8. Evaluation setup
- Main ranking metric: NDCG@10
- Second required metric: Novelty@10
- Extra sanity metric also reported: HitRate@10
- Evaluation user pool: users with at least 6 positive ratings
- Randomly selected evaluation users: 300
- Actually evaluated users: 104
- For each evaluated user:
  - hold out up to 3 positive movies
  - build profile without those held-out positives
  - candidate set = held-out positives + 100 sampled unseen negatives
  - rank candidates
  - compute HitRate@10, NDCG@10, Novelty@10

Why these metrics:
- NDCG@10 is suitable because the system outputs a ranked top-N list
- Novelty@10 is suitable because recommenders should not only be accurate but also avoid recommending only obvious popular films
- HitRate@10 is useful as an easy extra check for whether relevant held-out items appear in the top 10

9. Final evaluation results
RS1_TFIDF
- Users evaluated: 104
- HitRate@10: 0.932692
- NDCG@10: 0.475242
- Novelty@10: 24.135108

RS2_SBERT
- Users evaluated: 104
- HitRate@10: 0.730769
- NDCG@10: 0.273963
- Novelty@10: 27.405814

10. Main interpretation of results
- RS1 performed better on ranking accuracy
- RS2 performed better on novelty
- This suggests an accuracy–novelty trade-off
- TF-IDF worked well because MovieLens profile text contains direct genre/tag signals
- SBERT produced more exploratory or semantically broader recommendations
- RS2 did not outperform RS1 on ranking quality in this setup
- More advanced does not automatically mean better on every metric

11. Ethical / responsible AI notes — RS1
- Popularity bias: mainstream films may dominate recommendations
- Filter bubbles: content-based matching can keep recommending similar films
- Tag noise: user-generated tags can be subjective, messy, or inappropriate
- Cold start: users with very few ratings get weak profiles
- Strength: explanations are relatively transparent

12. Ethical / responsible AI notes — RS2
- Same risks as RS1: popularity bias, cold start, noisy tags, filter bubbles
- Additional issue: lower interpretability because semantic embeddings are harder to explain than TF-IDF
- Pretrained language models may inherit biases from their training data
- Recommendations may be semantically plausible but less directly explainable
- Strength: can surface less obvious, more novel items

13. RS1 vs RS2 comparison summary
- RS1:
  - stronger on HitRate@10
  - stronger on NDCG@10
  - more transparent
  - more literal / direct matching
- RS2:
  - stronger on Novelty@10
  - more semantic recommendations
  - less transparent
  - weaker ranking accuracy in this experiment
